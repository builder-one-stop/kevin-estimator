# Netlify beta activation

`onestop-beta.netlify.app` was serving commit `43831b5` from `feat/ai-estimator-approved-plan` on 2026-10-10. The repository and GitHub branch matched that commit before this work; only the existing untracked `design/` directory was present. The deployed root returned 200, while direct `/chat` and `/api/ai/status` returned 404. See `evidence/netlify-preflight-2026-10-10.json`.

The new `netlify.toml` builds Vite, serves client routes through the SPA fallback, and rewrites `/api/ai/*` to a Node Netlify Function. The regular function authenticates each bearer token against the verified Supabase project and stores a queued run. It invokes the authenticated background function, which claims the queued run once and performs the Responses call. Browser polling reads the committed result. Dispatch failure is persisted as `DISPATCH_UNAVAILABLE`, leaving the user's message for retry. A background run never reports success before its database commit. Local `npm run dev:api` keeps the original loopback server for development.

The Netlify site needs these variables. `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are public build values. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_REASONING_EFFORT`, and the optional `OPENAI_*_USD_PER_MILLION` rates are used by Functions. The current Netlify plan rejects function-only scopes, so these variables use the plan’s default scopes; the service-role and OpenAI keys are marked as Netlify secrets, which excludes post-processing and hides their values in Netlify. They are never VITE values or committed files. `SUPABASE_URL` must be `https://vtpciccluvpaclbeqxih.supabase.co`; model and effort are `gpt-6.1-sol` and `medium`. If needed, set `APP_ORIGIN` to `https://onestop-beta.netlify.app` only for the local server; the Netlify handler checks the request's own HTTPS origin. Environment changes require another build and deploy before functions see them.

Historical activation before closed-beta access: Supabase Auth on project `vtpciccluvpaclbeqxih` now has the beta origin in its redirect allowlist and the beta origin as Site URL. Existing MFA TOTP, email confirmations, 1-minute email frequency, and 8-digit OTP settings were restored after the CLI's first config push attempted to replace omitted values. A subsequent config push reported Auth up to date. Existing users can request a password link or use their sign-in link, then set a password with `updateUser`; the app also supports password login and signup in English and Spanish. Passwords are handled by Supabase Auth and are never stored in the application database.

The synchronous Netlify function limit is 60 seconds and the background function has a 15-minute execution limit. The backend's model timeout remains 120 seconds. Image upload input is capped at 4 MiB so its Base64 JSON body fits Netlify's 6 MB buffered request limit; the browser describes that limit. The local per-process write limiter does not act as a global serverless rate limit, so Netlify account limits and monitoring remain operational requirements. The database still enforces one active run per owner.

Independent local validation: 78 unit/integration tests passed; the controlled Chrome chat journey passed; the real Chrome password journey used a temporary Supabase account, set its password, signed out and signed in again in Spanish, then deleted that account. Both Netlify functions bundled locally; direct unauthenticated function calls returned 401. These local checks alone do not prove the deployed function has credentials or that a recovery email was delivered; the subsequent online checks below validate the deployed chat and estimate flow.

Online beta validation after commit `ceaf85a`: Netlify published that exact commit. Direct `/chat` and `/account/password` returned 200; unauthenticated `/api/ai/status` returned 401. In real Chrome with a temporary Supabase user (a generated link, no email sent), the beta answered “hola” with `gpt-6.1-sol` at medium effort, produced an approvable plan, generated a three-line estimate, and preserved an edited quantity after reopening and reloading. The same beta let an existing temporary link user set a password, sign out, and sign back in with email/password in Spanish. Both fixtures verified deletion of their own temporary users and records. See `evidence/ai-estimator-online/` and `evidence/browser-validation/password-access-online.json`. Delivery of signup and password-recovery emails was not tested by these fixtures.

The current closed-beta access rules supersede the historical signup, link and password-recovery behavior above. See [beta-access.md](beta-access.md) for the two-account password gate, read-only administrative review, session checks and the safe validation commands.

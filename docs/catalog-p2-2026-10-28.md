## Reproduction and corrections

Five initial regressions failed on ea669cc before implementation (`before-regressions.json`): changed product with inherited research category; legacy changed identity still eligible; unknown sourceId accepted; old unknown source rows disappeared; catalog lacked pagination. Tests then expanded to cover direct API writes, account isolation and raw historical snapshots.

1. `researchBindingIssue` checks the exact research product/brand/SKU/model/variant/package/unit binding. Changed identity imports are rejected with `RESEARCH_IDENTITY_CHANGED`, in preview and direct settings writes. For a different own product, messages require omitting sourceId and id to create a separate record without inherited research classification/technical coverage. Existing changed records retain their amounts and price history but their effective category, package/conversion metadata and technical profile are cleared, and classification remains explicitly pending. The common function matcher also checks the original binding, so raw historical snapshots cannot bypass this on new calculation or explicit recalculation. No category is inferred from the changed product's name. Saved estimates are not silently rewritten on load.
2. Unknown sourceId imports are rejected atomically with `UNKNOWN_RESEARCH_SOURCE` and a useful EN/ES explanation. Previously stored unknown bindings remain visible in the effective account catalog as pending records; they no longer disappear. Existing history is not deleted.
3. MaterialCatalogService now returns bounded limit1–40, offset0–1000 and nextOffset after account and role/text filters. PlanMaterials uses a function-specific server-search picker with180ms query debounce, actual AbortSignal cancellation, late-response suppression, explicit load-more, ID deduplication across pages, pending/empty/error/retry states and saved-selection preservation. No supplier request or external refresh is introduced. The API remains scoped to the authenticated owner's settings. Catalog writes remain admin-only.

Existing quantity/technical tests that deliberately mutate a research package, unit, product name or retail alias now mark those synthetic own products as unlinked rather than incorrectly retaining the sourceId. All numeric, rounding, manual-override and technical-evidence assertions remain. The change does not invent five-gallon catalog products or prices.
